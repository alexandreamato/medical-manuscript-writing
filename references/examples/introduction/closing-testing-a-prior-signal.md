# Closing: Testing a Prior Signal in a Stronger Design

`Use when the study was prompted by a pilot result, case series, registry trend, or mechanistic finding, and it tests that signal with a design able to confirm or refute it.`

## Skeleton

```
% State the prior signal and its source
[PILOT / CASE SERIES / REGISTRY] data suggested that [SIGNAL].

% State why the signal is not yet sufficient
Because [LIMITATION: small sample, no comparator, selection, post-hoc finding], this
observation requires confirmation.

% State the study that tests it
We therefore conducted a [DESIGN] in [POPULATION] to [estimate / test] [OUTCOME].

% State the practical stakes if confirmed or refuted
If confirmed, [CLINICAL CONSEQUENCE]; if not, [CONSEQUENCE].
```

## Worked example (illustrative; fictional)

```
In a single-centre series of 42 patients with previously treated metastatic breast
cancer, tumours scored HER2 1+ by immunohistochemistry showed objective responses to an
antibody-drug conjugate at rates similar to tumours scored 2+. Because the series was
small, retrospective, and lacked central pathology review, this observation requires
confirmation. We therefore conducted an open-label, single-arm phase 2 trial in 180
patients to estimate the objective response rate and its duration across centrally
reviewed HER2 immunohistochemistry strata. If confirmed, these findings would support
evaluating the drug in a randomized trial in the HER2 1+ population.
```

## Notes and pitfalls

1. The prior signal must exist before the study and be cited. Never construct a pilot result to motivate a design after the fact.
2. State what the new design can and cannot establish. A single-arm trial estimates response; it does not establish comparative efficacy.
3. The consequence sentence should be proportionate: a phase 2 result justifies a phase 3 trial, not a change in practice.
